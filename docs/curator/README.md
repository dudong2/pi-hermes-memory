# Skill Curator — 단계 E: 독립 주기 실행

## 구현 범위

- `SkillStore`의 실제 생성 성공 경계에 생성 원장을 연결한다. 수정·삭제·범위 이동도 같은 잠금 경계에서 기록한다.
- 전역·프로젝트 스킬을 읽기 전용으로 조사하고, 생성 경계 확인·과거 생성 이력 일치·출처 불명을 구분한다.
- 성공한 읽기·특정 스킬 조회·검증된 명시 호출을 관측하고, 세션별 관측 구간과 장애를 기록한다.
- 명시적으로 설정한 기간과 보호 조건으로 후보·보류 이유와 기간 경계를 계산하는 읽기 전용 dry-run을 제공한다.
- 확인된 관리 대상이 조건을 충족하면 별도 승인·알림 없이 제거하는 엔진을 제공한다. 삭제 이력·보관소·복원은 없다.
- Pi 밖에서 단발·주기 실행하는 CLI를 제공한다. 예약 작업·데몬은 자동 설치하지 않는다. dry-run의 `cleanupEligible`은 여전히 `false`이며, 제거 엔진이 직전 검증을 별도로 수행한다.

## 사용법

```text
/memory-curator status
/memory-curator inventory
/memory-curator dry-run
/memory-curator remove
```

현재 전역 루트와 명령 실행 위치에 해당하는 프로젝트 루트만 조사한다. 전체 홈이나 과거 세션을 기본으로 스캔하지 않는다.
조회는 대화형 알림 또는 비대화형 `curator-inventory` 메시지로 표시한다. `remove`는 확인 질문·개별 삭제 알림 없이 동작한다.

설정 파일의 `curatorEnabled` 기본값은 `true`다. 이는 출처·활동 판단 상태를 활성화한다. 조건부 제거는 사용자가 승인한 에이전트 생성 관리 대상에만 한정하며, 수동·외부·출처 불명 스킬로 범위를 확대하지 않는다.
`false`로 설정하면 기록과 제거를 끄고, 기존 원장과 스킬 파일은 그대로 둔다. `curatorPaused: true`는 제거만 중지하고 출처·활동 관측은 유지한다. 유효하지 않은 활성화·pause 값으로 제거 권한을 얻을 수 없다.

## 독립 실행기

```bash
# 저장소에서 한 번 검사
node scripts/curator.mjs --once

# 명시한 간격으로 반복 검사 — 60은 실행 간격 예시이며 미사용 기간 기본값이 아니다
node scripts/curator.mjs --watch --interval-minutes 60

# npm 설치가 bin을 제공하는 환경에서 같은 실행기를 호출
pi-hermes-curator --watch --interval-minutes 60
```

- `PI_CODING_AGENT_DIR` 또는 기본 agent 디렉터리의 현재 설정을 매 회 읽는다. 미설정·불완전·잘못된 정책에서는 제거하지 않는다.
- 현재 전역 루트와 **원장에 이미 확인된 프로젝트 이름**만 사용한다. 프로젝트 발견을 위해 홈이나 임의 저장소를 스캔하지 않는다. 경로 이탈 이름은 제외한다.
- Pi가 스킬을 캐시한 채 살아 있으면 보류한다. 독립 실행기는 Pi 세션·모델·활동 관측 구간을 새로 만들지 않는다.
- 실행은 직렬이며 밀린 실행을 몰아서 처리하지 않는다. 실패하면 다음 지정 간격에 재평가하며, 과거 삭제 의도를 재생하거나 별도 이력을 남기지 않는다.
- 제거 직전에 설정·pin·pause·루트 변경을 재확인한다. `curatorPaused`를 해제하거나 정책을 수정하면 다음 검사에 반영된다.
- `SIGINT`·`SIGTERM`은 진행 중인 작업을 안전하게 마친 뒤 중지한다. 이후 대상의 새 제거는 시작하지 않는다. 삭제 알림과 대상별 출력은 없다.
- 정상 단발 실행은 출력 없이 종료하며, 저장소 오류는 비정상 종료 코드로 전달한다. 주기 모드는 알림 없이 재평가한다.
- 확인된 종료 프로세스의 미완료 관측은 마지막 확인 시점에 `faulted`로 닫고 공백을 남긴다. 종료 이후 시간을 정상 관측으로 합산하지 않는다. 살아 있거나 소유를 확인할 수 없는 프로세스의 구간은 그대로 보호한다.
- OS 예약 도구에서는 단발 실행을 호출하거나 주기 모드 프로세스를 관리할 수 있다. **이번 구현은 실제 예약 작업·데몬·사용자 설정을 설치하거나 변경하지 않는다.**

## 세대와 출처

- 기록 대상 신규 생성에는 `pi-hermes-generation` UUID를 frontmatter에 추가한다. 표식 자체는 관리 권한의 증거가 아니다.
- 표식·현재 파일 해시·파일 식별자·경로·범위가 원장과 모두 일치해야 현재 세대를 확인한 것으로 표시한다.
- 삭제 후 같은 내용으로 재생성되어도 새 UUID를 부여한다. 기록 실패나 프로세스 중단으로 원장에 이전 세대가 남아도 새 파일에 연결하지 않는다.
- 수정과 이동은 이미 확인된 세대에만 연결한다. 조회·수정만으로 외부 스킬을 신규 등록하지 않는다.
- 기록 실패가 완료된 파일 작업을 실패로 뒤집지는 않는다. 원장 손상은 복구를 추정하지 않고 경고와 부분 보고서로 남긴다.

`history.ts`는 명시적으로 전달한 Pi v3 JSONL 파일만 제한된 크기로 읽는다. 직접 생성 요청과 성공 결과를 연결하고,
복사된 이벤트는 중복 제거한다. 중첩 호출 메타데이터는 미확정 건수만 표시하며 관리 권한을 부여하지 않는다.

과거 이력이 일치해도 `generation: unverified`다. 기존 스킬 편입은 현재 파일과 생성 출처를 사용자가 확인하는 별도 절차로 추가해야 한다.
기존 스킬을 삭제·재생성해 원장에 넣는 방식은 권장하지 않는다.

## 활동과 관측 범위

- `tool_call` 시 현재 세대를 확인하고, 성공한 `tool_result` 시 파일·세대를 재검증한다. 중복 결과는 한 번만 기록한다.
- `skill_manage(view)`는 특정 ID의 성공 결과를 확인한다. 목록 조회·내부 파일 읽기·실패 결과는 활동이 아니다.
- `/skill:`은 원래 입력과 실제 전달된 스킬 블록의 경로·본문 해시를 연결할 수 있을 때만 기록한다. 입력만 보고 사용으로 판단하지 않는다.
- 설치된 SDK의 `prompt(..., { source: "rpc", streamingBehavior: "steer" | "followUp" })` 큐 경로를 검증한다.
- SDK의 직접 `steer()`·`followUp()`은 입력 근거 없이 확장될 수 있다. 이 경우 활동을 추정하지 않고 `unconfirmed-skill-command` 공백으로 남긴다.
- 중첩 호출은 실제 자식 콜백이 있을 때만 기록한다. 메타데이터만 있거나 불완전하면 관측 공백으로 남긴다.
- 관측 실패·미완료 호출·시계 역행은 `faulted`로 기록한다. 중단되어 닫히지 않은 구간은 그대로 유지한다.
- `observation.supportedPaths`는 지원 범위이며 `allPathsObserved`는 항상 `false`다. 외부 도구·셸 등 모든 사용 경로의 관측을 보장하지 않는다.
- `lastActivityAt: null`과 관측 구간 사이의 공백은 미사용 근거가 아니다. 이후 후보 정책은 공백과 열린 구간을 반드시 고려해야 한다.
- 관리 대상이 없으면 관측을 위해 DB를 만들지 않는다. 이전 v1 원장은 최초 쓰기에서 v3로 원자적으로 확장하고, 조회만으로 마이그레이션하지 않는다.

## 후보 정책과 dry-run

`hermes-memory-config.json`의 `curatorPolicy`에 기간을 명시해야 한다. 기본 기간은 없으며 미설정·불완전·잘못된 설정은 보류한다.
아래 여섯 기간은 모두 필수다. 비활동·최소 관측 기간은 양수, 나머지는 0 이상인 유한한 숫자이며 밀리초 정밀도로 표현 가능해야 한다.

| 설정 | 의미 |
|---|---|
| `inactivityDays` | 지원 경로에서 활동 없이 연속 관측되어야 하는 기간 |
| `minimumObservationDays` | 현재 세대·초기 편입 이후 필요한 최소 정상 관측 기간 |
| `creationGraceDays` | 생성 유예기간 |
| `modificationGraceDays` | 수정·이동 유예기간 |
| `adoptionGraceDays` | 향후 명시적 초기 편입 유예기간; 현재 편입 기능 자체는 없음 |
| `maxObservationAgeDays` | 마지막 확정 관측 시점에 대한 보고서 신선도 허용기간 |

선택 설정 `pinnedSkillIds`는 보호할 안정적인 스킬 ID 목록이다. 예를 들어 `global:release-check`나 `project:app:build-check`다.
이는 보호 규칙일 뿐 출처 확인이나 관리 권한을 부여하지 않는다. pin/unpin 명령과 자동 운영은 이후 단계다.

- 정상 종료된 `pi-hooks-v1` 구간 중 **가장 최근의 연속 구간**만 사용한다. 겹치는 시간은 중복 계산하지 않고, 중간 공백 이전의 구간은 합산하지 않는다.
- 생성·수정·최근 활동·초기 편입 시점과 구간 시작 이후의 관측 시간만 계산한다. `lastActivityAt: null`만으로 미사용을 추정하지 않는다.
- pin·사용 중·출처 불명·불확실한 세대·관측 장애·미지원 관측자·잘못된 시각은 보류한다.
- 현재 원장은 열린 구간을 루트별로 안전하게 구분할 수 없으므로, 열린 구간이 하나라도 있으면 모든 관리 대상의 정리 후보를 보수적으로 보류한다.
- 관측 종료 이후의 시간은 비활동 기간에 더하지 않는다. `observationAsOfAt`은 판단 기준 시점이며 `maxObservationAgeDays`는 시간 합산이나 정리 승인이 아니다.
- `candidate: true`는 **지원된 경로와 확인된 과거 구간 안의 미리보기**다. 모든 사용 경로의 미사용 확정이나 자동 정리 허용을 뜻하지 않는다.
- 파일 검증 지문과 같은 세대의 메타데이터를 비교하고, 활동 시각·관측 구간은 하나의 읽기 전용 SQLite 스냅샷으로 읽는다.
- dry-run은 스킬·부속 파일·원장의 내용을 변경하거나 DB를 새로 만들지 않는다. 실제 제거는 별도의 직전 재검증·공통 잠금·프로세스 캐시 보호를 거친다.

## 조건부 제거

- `removeUnusedSkills()`는 대상 선택·조건 판단을 수행한다. 개별 확인, 삭제 이력, 복원 정보, 장기 보관본은 만들지 않는다.
- 제거 직전에 최신 정책·pin·활동·세대·해시를 다시 확인한다. 공유 변경 잠금은 관측을 끈 Pi의 스킬 수정에도 적용한다.
- 관측 종료와 프로세스 종료는 다르다. 닫힌 구간이라도 원래 프로세스가 살아 있거나 PID 재사용을 구분할 수 없으면 보류한다.
- 리소스 발견도 같은 생명주기 잠금 아래에서 현재 캐시 소유 프로세스를 등록한다. 캐시 소유 상태는 판단용이며 삭제 기록이 아니다.
- 기존 구간에 소유 PID가 없으면 종료를 추정하지 않는다. 실제 프로세스 종료를 확인할 수 없으면 제거하지 않는다.
- 현재 관측은 `SKILL.md` 기준이다. scripts·references·assets 등 부속 파일이 있는 스킬은 그 사용을 증명할 수 없으므로 **전부 보류**한다. 심볼릭 링크·하드링크·경로 이탈도 제외한다.
- 현재 세대의 삭제 권한을 먼저 없앤 뒤 파일을 제거한다. 중단·I/O 오류 시 남은 파일은 자동으로 재등록하거나 과거 삭제 의도로 재시도하지 않는다.
- `SKILL.md`만 제거하고 빈 디렉터리에만 `rmdir`을 적용한다. 새로 추가된 파일은 재귀 삭제하지 않는다.
- 남는 것은 미삭제 대상의 현재 출처·세대·활동 판단 상태다. 제거된 세대와 그 활동은 지우고, 작업 이력 테이블과 삭제 tombstone은 보존하지 않는다.
- 조회·dry-run과 달리 제거는 되돌릴 수 없다. 현재 설치본과 실제 사용자 스킬을 대상으로 시험하지 않는다.

## 저장과 보호

- `${PI_CODING_AGENT_DIR}/pi-hermes-memory/curator/curator.db`에 출처·세대·활동·관측 공백·캐시 소유 판단 상태를 저장한다. 삭제 이력은 저장하지 않는다. 기본 agent 디렉터리는 `~/.pi/agent`다.
- 메모리의 `sessions.db`와 분리하고, 기존 SQLite 런타임과 프로세스 간 잠금을 사용한다. 새 네이티브 의존성은 없다. CLI는 Pi에서도 사용하는 `jiti`를 직접 런타임 의존성으로 선언하여, 개발용 `tsx`나 package-local SDK 없이도 실행한다.
- 원장 디렉터리는 `0700`, DB와 잠금 DB는 `0600`으로 보호한다. 본문·프롬프트·절대 경로는 기록하거나 출력하지 않는다.
- 사용자 설정으로 agent 디렉터리 밖에 둔 스킬 루트는 해시로 식별하고, 실제 경로는 현재 설정에서 해석한다.
- 조사 시 심볼릭 링크·하드링크·읽는 중 변경된 파일·읽기 제한 초과를 보수적으로 제외한다.

## 다음 단계

- 부속 파일 사용 관측을 확장한 뒤 해당 스킬의 제거 범위를 넓힌다.
- 실제 운영 설치는 별도 적용 단계다. 현재는 임시 환경에서만 실행·검증한다.

앞선 전달 문서의 보관·복원 설계는 사용자의 최신 제거 중심 요구로 대체됐다. 보관·복원용 Python helper는 사용하지 않는다.

## 검증

실제 사용자 데이터 대신 임시 agent 디렉터리·스킬·세션에서 검사한다.
SDK 테스트는 실제 SDK의 확장·큐 메서드를 실행하되 agent 전달 지점만 대체한다. 실제 모델 호출이나 라이브 UI 검증을 대신하지 않는다.
